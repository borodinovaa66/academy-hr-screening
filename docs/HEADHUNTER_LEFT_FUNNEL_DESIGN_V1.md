# Левая часть воронки подбора: HeadHunter и запуск вакансии v1

## 1. Что мы строим

Мы расширяем платформу подбора влево: от момента, когда у руководителя появляется потребность в сотруднике, до момента, когда кандидат с HeadHunter попадает в нашу анкету на платформе.

Цепочка:

1. Руководитель инициирует подбор.
2. Выбирает готовую вакансию из справочника или создает запрос на новую.
3. HR подтверждает запуск и, если нужно, дорабатывает карточку вакансии.
4. Платформа готовит текст вакансии для HeadHunter.
5. HR проверяет текст и запускает публикацию.
6. Платформа публикует вакансию на HeadHunter через API или готовит ручную публикацию.
7. Платформа получает отклики.
8. Платформа отправляет откликнувшимся кандидатам сообщение со ссылкой на нашу анкету.
9. Кандидат переходит на нашу платформу и входит в текущую воронку.

## 2. Роли

| Роль | Что может делать |
| --- | --- |
| Владелец | Видит все вакансии, сотрудников, журнал, интеграции, настройки HeadHunter |
| HR | Создает новые вакансии, редактирует карточки, запускает публикацию, видит все отклики |
| Руководитель-заказчик | Запускает подбор только по готовым вакансиям, к которым у него есть доступ; создает запрос на новую вакансию; видит только свои вакансии |
| Кандидат | Откликается на HeadHunter, получает ссылку, проходит анкету |

Ключевое решение: руководитель-заказчик не создает новую вакансию напрямую. Он создает запрос. Новую вакансию в справочнике создает HR.

## 3. Основные сущности платформы

### 3.1. Справочник должностей

Это база ролей компании, даже если подбор по ним сейчас не открыт.

Поля:

- код должности;
- название должности;
- направление / отдел;
- грейд;
- подчинение;
- тип роли: штат / проект / подряд;
- руководитель по умолчанию;
- статус: активна / архив / черновик;
- ссылка на карточку роли;
- дата последнего обновления.

### 3.2. Карточка вакансии

Это конкретная вакансия, которую можно запускать в подбор.

Поля:

- код вакансии;
- должность из справочника;
- публичное название;
- внутреннее название;
- руководитель-заказчик;
- HR-ответственный;
- причина открытия: замена / расширение / новая роль / временный проект;
- сколько человек нужно;
- формат работы;
- занятость;
- город / удаленно;
- зарплатная вилка;
- требования;
- обязанности;
- условия;
- преимущества роли;
- этапы воронки;
- ссылка на анкету;
- тестовое задание;
- скрипты интервью;
- текст вакансии для HeadHunter;
- текст сообщения кандидату после отклика;
- статус: черновик / готова / опубликована / на паузе / закрыта.

### 3.3. Заявка на запуск подбора

Создается руководителем, когда он хочет начать подбор.

Поля:

- инициатор;
- выбранная должность / вакансия;
- причина открытия;
- срочность;
- желаемая дата выхода;
- сколько человек нужно;
- комментарий руководителя;
- статус: новая / на уточнении / принята / отклонена / запущена;
- решение HR;
- связанная вакансия.

### 3.4. Запрос на новую вакансию

Создается руководителем, если нужной вакансии нет в справочнике.

Минимальные поля для руководителя:

- кого ищем простыми словами;
- зачем нужна роль;
- какие задачи человек должен закрыть;
- кому будет подчиняться;
- почему нельзя закрыть задачами текущей команды;
- какой ожидаемый результат через 1-3 месяца;
- срочность;
- предполагаемый доход / бюджет;
- комментарии и ссылки на примеры похожих вакансий.

После этого HR дорабатывает запрос до полноценной карточки вакансии.

### 3.5. Публикация на HeadHunter

Поля:

- внутренняя вакансия;
- HeadHunter ID вакансии;
- работодатель HeadHunter;
- статус публикации;
- дата публикации;
- дата обновления;
- пакет / тип публикации;
- ссылка на вакансию на HeadHunter;
- текст публикации;
- ссылка на нашу анкету с метками;
- ошибки публикации;
- модерационный статус.

### 3.6. Отклик HeadHunter

Поля:

- HeadHunter ID отклика;
- HeadHunter ID резюме;
- HeadHunter ID вакансии;
- внутренняя вакансия;
- имя кандидата, если доступно;
- ссылка на резюме;
- статус отклика;
- дата отклика;
- был ли отправлен наш ответ;
- текст отправленного сообщения;
- дата отправки сообщения;
- перешел ли кандидат на нашу анкету;
- заполнил ли анкету;
- связанная карточка кандидата на нашей платформе.

## 4. Пользовательский сценарий

### Сценарий 1. Запуск готовой вакансии

1. Руководитель входит в личный кабинет.
2. Открывает раздел `Мои вакансии`.
3. Нажимает `Запустить подбор`.
4. Выбирает вакансию из доступного справочника.
5. Заполняет короткую заявку:
   - причина открытия;
   - сколько человек нужно;
   - желаемая дата выхода;
   - срочность;
   - комментарий.
6. HR получает уведомление.
7. HR проверяет карточку вакансии.
8. HR нажимает `Подготовить публикацию`.
9. Платформа собирает текст HeadHunter.
10. HR проверяет текст и нажимает `Опубликовать`.
11. Платформа размещает вакансию или создает готовый пакет для ручной публикации.
12. Воронка получает статус `Опубликована`.

### Сценарий 2. Нужной вакансии нет

1. Руководитель нажимает `Запросить новую вакансию`.
2. Заполняет короткий запрос на новую роль.
3. HR получает запрос.
4. HR проводит уточнение с руководителем.
5. HR создает карточку вакансии:
   - описание роли;
   - требования;
   - текст HeadHunter;
   - входной опросник;
   - тестовое задание;
   - критерии оценки;
   - этапы воронки.
6. Вакансия попадает в справочник.
7. Руководитель получает доступ к этой вакансии.
8. Дальше процесс идет как запуск готовой вакансии.

## 5. Алгоритм создания новой вакансии HR

HR должен собрать:

1. Бизнес-причину:
   - замена;
   - рост нагрузки;
   - новая функция;
   - проектная роль.

2. Результат роли:
   - что человек должен изменить в бизнесе;
   - какие показатели или зоны ответственности берет на себя;
   - что считается успешным испытательным сроком.

3. Функционал:
   - регулярные задачи;
   - проектные задачи;
   - границы ответственности;
   - что точно не входит в роль.

4. Требования:
   - обязательный опыт;
   - желательный опыт;
   - инструменты;
   - стоп-факторы.

5. Условия:
   - формат;
   - занятость;
   - доход;
   - график;
   - подчинение;
   - команда.

6. Материалы воронки:
   - текст HeadHunter;
   - текст Telegram-поста;
   - входной опросник;
   - тестовое задание;
   - скрипт интервью HR;
   - скрипт интервью руководителя;
   - критерии оценки;
   - шаблон офера.

## 6. Методология текста вакансии для HeadHunter

Текст должен не просто описывать требования, а продавать компанию, роль и смысл работы.

Структура:

1. Заголовок вакансии.
2. Короткое сильное вступление: кто мы и почему роль интересная.
3. Почему открыта позиция.
4. Что человек будет делать.
5. Какой результат от него ждут.
6. Кому подойдет эта роль.
7. Кому точно не подойдет.
8. Что мы предлагаем.
9. Как проходит отбор.
10. Призыв к отклику и переходу на анкету.

Принципы:

- сначала продаем компанию и роль;
- не начинаем с сухих требований;
- пишем человеческим языком;
- не обещаем того, чего нет;
- показываем смысл работы, масштаб задач и развитие;
- отдельно подсвечиваем, чем роль интересна сильному кандидату.

## 7. Сообщение откликнувшемуся кандидату

Цель сообщения: перевести кандидата из отклика HeadHunter в нашу анкету.

Текст должен быть:

- коротким;
- человеческим;
- без ощущения бота;
- с объяснением, зачем нужна анкета;
- с обещанием разумного времени прохождения;
- с прямой ссылкой.

Шаблон:

```text
Здравствуйте, {{candidateName}}!

Спасибо за отклик на вакансию {{vacancyTitle}} в Академии менеджмента.

Мы смотрим не только резюме, но и то, как человек думает в рабочих ситуациях. Поэтому первый шаг у нас — короткая анкета на 7-10 минут.

Пожалуйста, заполните ее здесь:
{{questionnaireLink}}

После анкеты мы сможем быстрее понять, насколько роль вам подходит, и вернуться с понятным следующим шагом.
```

Вариант короче:

```text
Здравствуйте!

Спасибо за отклик на вакансию {{vacancyTitle}}.

Чтобы мы быстрее рассмотрели вашу кандидатуру, заполните короткую анкету на 7-10 минут:
{{questionnaireLink}}

Анкета помогает нам оценить не только резюме, но и ваш подход к рабочим ситуациям.
```

## 8. Интеграция с HeadHunter

По официальной документации HeadHunter API требует регистрацию приложения, OAuth-авторизацию и позволяет работать с вакансиями, резюме, откликами и сообщениями. Для работодателя при получении откликов используется фильтр по `vacancy_id`. Сообщение по отклику отправляется через endpoint вида `POST /negotiations/{nid}/messages`.

Нам нужны интеграционные блоки:

1. OAuth-подключение работодателя HeadHunter.
2. Хранилище токенов.
3. Справочники HeadHunter:
   - регионы;
   - опыт;
   - график;
   - занятость;
   - специализации;
   - валюта;
   - типы вакансий.
4. Публикация вакансии.
5. Получение статуса публикации.
6. Получение откликов по вакансии.
7. Получение резюме / кратких данных отклика.
8. Отправка сообщения кандидату.
9. Защита от повторной отправки.
10. Журнал интеграционных событий.

## 9. Важные ограничения

1. HeadHunter может модерировать текст вакансии и внешние ссылки.
2. Автопубликация зависит от тарифа, прав работодателя и оплаченных публикаций.
3. Нельзя слать одно и то же сообщение бесконтрольно всем кандидатам без учета правил платформы.
4. Нужно хранить согласия и источник кандидата.
5. Персональные данные из резюме нужно хранить минимально и только по делу.
6. Нужен журнал: кто запустил публикацию, кто отправил сообщения, какие ошибки были.

## 10. MVP

Первую рабочую версию лучше делать в 3 этапа.

### Этап 1. Без API HeadHunter

Цель: быстро дать HR управляемый процесс.

Функции:

- справочник вакансий;
- заявка руководителя на запуск подбора;
- запрос на новую вакансию;
- статус вакансии;
- генерация текста HeadHunter;
- генерация ссылки на анкету;
- ручная публикация HR;
- ручной импорт или отметка источника `HeadHunter`.

### Этап 2. Полуавтоматическая интеграция

Функции:

- подключение HeadHunter через OAuth;
- сохранение HeadHunter ID вакансии;
- получение откликов;
- список откликов в нашей платформе;
- кнопка `Отправить ссылку на анкету`;
- защита от повторной отправки;
- журнал отправок.

### Этап 3. Автоматизация

Функции:

- публикация вакансии через API;
- обновление вакансии через API;
- автоматический сбор новых откликов по расписанию;
- автоматическая отправка сообщения с анкетой;
- дашборд конверсий:
  - просмотры HeadHunter;
  - отклики;
  - отправленные сообщения;
  - клики по ссылке;
  - начатые анкеты;
  - завершенные анкеты;
  - допущенные до тестового;
  - допущенные до интервью.

## 13. Критерии готовности первой версии

Версия считается готовой, если:

- руководитель может запустить подбор по готовой вакансии;
- руководитель может создать запрос на новую вакансию;
- HR видит запросы и создает вакансию;
- HR получает готовый текст HeadHunter;
- HR получает ссылку на анкету;
- источник кандидата `HeadHunter` сохраняется;
- в админке видна связка: вакансия → публикация → отклики → анкеты → кандидаты.
