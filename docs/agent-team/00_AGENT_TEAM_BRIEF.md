# Общая инструкция для агентской команды HR-платформы

## 1. Что за проект

Мы развиваем HR-платформу Бизнес-школы "Академия менеджмента" в самостоятельный коммерческий продукт.

Платформа автоматизирует первичный отбор кандидатов:

1. Руководитель или HR запускает подбор по вакансии.
2. Система готовит или использует готовую вакансию, анкету, тестовое задание и критерии оценки.
3. Вакансия продвигается через hh.ru и профессиональные каналы.
4. Кандидат проходит короткую анкету в формате чат-опроса.
5. Платформа считает оценку, риски, сильные стороны и рекомендацию.
6. Сильным кандидатам выдается тестовое задание.
7. Тестовое оценивает руководитель, а искусственный интеллект дает второе мнение.
8. HR и руководитель получают дашборд, карточки кандидатов, уведомления и рекомендации по следующим шагам.

Цель продукта: сократить ручную работу HR и руководителя на ранней стадии подбора, повысить качество фильтрации и не терять сильных кандидатов в длинной переписке.

## 2. Для кого продукт

Основные пользователи:

## 5. Принципы продукта

- Первый этап для кандидата должен занимать 7-10 минут.
- Анкета не заменяет интервью, а решает: стоит ли тратить время интервьюера.
- Большинство вопросов закрытые, открытые вопросы короткие.
- Кандидатский интерфейс дружелюбный, в формате пошагового диалога.
- Админка строгая, рабочая, без декоративного шума.
- В интерфейсе для русскоязычных пользователей используем русский язык. Английские слова допустимы только как устойчивые названия сервисов или ролей, например hh.ru, Google Документ, SMM-менеджер.
- Искусственный интеллект помогает, но не принимает финальные кадровые решения.
- Руководитель и HR остаются в контуре проверки на важных этапах.

## 6. Роли агентов

### Разработчик

Основной исполнитель технических задач. Берет задачи из GitHub Issues, дорабатывает код, проверяет, деплоит, фиксирует изменения в GitHub.

### Маркетолог

Отвечает за позиционирование, упаковку, каналы продвижения, офферы, тексты, гипотезы продаж, анализ рынка и конкурентную рамку.

### Продакт-менеджер

Отвечает за продуктовую стратегию, сегменты клиентов, дорожную карту, приоритизацию функций, монетизацию и требования к MVP/релизам.

### Дизайнер интерфейса

Отвечает за пользовательский опыт, визуальную систему, сценарии экранов, удобство админки, кандидатский путь и макеты.

## 7. Как агенты взаимодействуют

Главный канал передачи задач в разработку - GitHub Issues в репозитории `academy-hr-screening`.

Каждый агент:

1. Изучает общий бриф и свой ролевой бриф.
2. Формирует результат своей работы в документе или задаче.
3. Если нужна разработка, создает GitHub Issue по шаблону `Agent task`.
4. В задаче указывает роль, бизнес-цель, пользовательский сценарий, требования и критерии приемки.
5. Разработчик берет задачу в работу, реализует, деплоит и закрывает issue.

Если у агента нет доступа к GitHub, временный запасной вариант:

1. Создать файл в `docs/agent-team/inbox/`.
2. Назвать файл по формату `YYYY-MM-DD_role_short-task.md`.
3. Описать задачу по структуре из `04_TASK_HANDOFF_TO_DEVELOPMENT.md`.
4. Попросить владельца или разработчика перенести задачу в GitHub Issue.

## 8. Что нельзя делать агентам

- Нельзя отправлять секреты, ключи, пароли и токены в документы, чаты или задачи.
- Нельзя менять код в продакшне без разработчика.
- Нельзя обещать клиентам функции, которых нет в продукте.
- Нельзя писать интерфейсные тексты на английском без необходимости.
- Нельзя автоматизировать кадровое решение так, чтобы человек был исключен из финального решения.
- Нельзя использовать реальные персональные данные кандидатов в маркетинговых материалах.

## 9. Что считается хорошим результатом агента

Хороший результат должен быть превращаемым в действие:

- готовый текст;
- гипотеза продвижения;
- макет;
- пользовательский сценарий;
- список требований;
- GitHub Issue для разработки;
- решение по приоритетам;
- критерии приемки.

Не нужен абстрактный анализ без следующего шага.
