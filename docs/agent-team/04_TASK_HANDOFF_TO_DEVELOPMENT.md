# Регламент передачи задач разработчику

## 1. Главный принцип

Агенты не должны пересылать задачи владельцу проекта вручную. Все задачи, требующие разработки, должны попадать в единый технический вход.

Основной вход:

- GitHub Issues в репозитории `academy-hr-screening`.

Репозиторий:

- `https://github.com/borodinovaa66/academy-hr-screening`

Шаблон:

- `Agent task`

## 1.1. Ветки агентов

Каждый агент работает в своей ветке и не смешивает изменения с другими ролями.

Рекомендуемые имена веток:

- маркетолог: `agent/marketing/<short-topic>`;
- продакт-менеджер: `agent/product/<short-topic>`;
- дизайнер: `agent/design/<short-topic>`;
- другой агент: `agent/<role>/<short-topic>`.

Агенты могут добавлять и редактировать свои документы в:

- `docs/agent-team/marketing/`;
- `docs/agent-team/product/`;
- `docs/agent-team/design/`;
- `docs/agent-team/inbox/`.

Агенты не меняют рабочий код приложения напрямую, если это не согласовано отдельно. Если изменение требует кода, агент создает GitHub Issue.

## 2. Когда создавать задачу

Создавай задачу, если нужно:

- изменить интерфейс;
- добавить экран;
- изменить текст в продукте;
- добавить аналитику;
- добавить интеграцию;
- поменять логику воронки;
- добавить новое состояние;
- исправить баг;
- подготовить демонстрационный режим;
- добавить метрику для маркетинга или продаж.

Не создавай задачу, если это пока только размышление. Сначала оформи гипотезу или документ.

## 3. Структура задачи

В GitHub Issue обязательно заполнить:

1. Роль агента: маркетолог, продакт-менеджер, дизайнер, другой агент.
2. Бизнес-цель.
3. Пользовательский сценарий.
4. Что нужно изменить.
5. Где менять: экран, раздел, файл или процесс.
6. Тексты, если они уже готовы.
7. Данные и события, если нужны.
8. Критерии приемки.
9. Приоритет.
10. Риски или ограничения.

## 4. Формат хорошей задачи

```md
## Цель
Сократить ручную работу HR при проверке новых откликов.

## Пользовательский сценарий
HR открывает вакансию, видит сколько приглашений отправлено сегодня и сколько анкет заполнено.

## Что нужно сделать
В дашборде вакансии добавить компактный блок:
- отклики hh.ru: всего / сегодня;
- приглашения отправлены: всего / сегодня;
- анкеты заполнены: всего / сегодня.

## Критерии приемки
- значения считаются отдельно за все время и за сегодня;
- блок не растягивает экран;
- если данных нет, показывается 0, а не пустота;
- на мобильном блок не ломает верстку.
```

## 5. Как разработчик берет задачу

Разработчик:

1. Проверяет новые Issues с меткой `agent-task`.
2. Уточняет требования в комментарии, если данных не хватает.
3. Создает ветку или работает в текущей рабочей ветке по договоренности.
4. Реализует.
5. Проверяет локально.
6. Деплоит на сервер, если задача готова к проверке.
7. Комментирует в Issue:
   - что сделано;
   - где смотреть;
   - какие проверки выполнены;
   - что осталось вне задачи.
8. Закрывает Issue после приемки.

## 6. Метки GitHub Issues

Рекомендуемые метки:

- `agent-task` - задача от агента;
- `needs-dev` - нужна разработка;
- `marketing` - от маркетолога;
- `product` - от продакт-менеджера;
- `design` - от дизайнера;
- `bug` - ошибка;
- `priority-high` - высокий приоритет;
- `priority-medium` - средний приоритет;
- `priority-low` - низкий приоритет.

Если метки еще не созданы в GitHub, разработчик или владелец создаст их при первом использовании.

## 7. Запасной вариант без GitHub

Если агент не может создать GitHub Issue:

1. Создать файл в папке `docs/agent-team/inbox/`.
2. Название: `YYYY-MM-DD_role_short-task.md`.
3. Описать задачу по структуре выше.
4. Сообщить владельцу проекта, что задача лежит в папке входящих.

Это временный вариант. Рабочий стандарт - GitHub Issues.

## 8. Что нельзя писать в задачах

Нельзя указывать:

- пароли;
- токены;
- ключи;
- приватные ссылки с доступом к персональным данным;
- реальные персональные данные кандидатов;
- содержимое env-файлов;
- закрытые финансовые условия клиентов.

## 9. Как задавать вопросы разработчику

Вопросы по конкретной задаче задаются в комментариях к GitHub Issue.

Если вопрос общий, создать Issue типа:

`[Вопрос] Тема вопроса`

и указать, почему ответ нужен для работы агента.
