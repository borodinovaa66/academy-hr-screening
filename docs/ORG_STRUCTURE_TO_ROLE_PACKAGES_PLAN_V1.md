# План сборки оргструктуры и пакетов ролей v1

## 1. Что мы на самом деле делаем

Мы берем накопленные документы по подбору и оргструктуре, приводим их к единой системе и превращаем в управляемые справочники платформы.

Цель: получить согласованную организационную структуру компании, затем по ней собрать список ролей и для каждой роли подготовить пакет подбора.

## 2. Последовательность работы

| Этап | Что делаем | Результат |
| --- | --- | --- |
| 1. Инвентаризация источников | Собираем все документы по оргструктуре, ролям, анкетам, тестовым, предложениям работы | Реестр источников |
| 2. Сбор вариантов оргструктуры | Читаем таблицы, документы, презентации и PDF по структуре компании | 2-3 варианта оргструктуры |
| 3. Сводная оргструктура | Объединяем варианты, убираем дубли, отмечаем спорные места | Черновик финальной структуры |
| 4. Согласование с Андреем | Показываем структуру: направления, роли, подчинение, пустые места | Утвержденная версия |
| 5. Список ролей | По оргструктуре формируем полный справочник ролей | Таблица ролей |
| 6. Приоритизация ролей | Выбираем роли, под которые нужны вакансии в первую очередь | Очередь разработки пакетов |
| 7. Пакеты ролей | Для каждой роли создаем карточку, вакансию, анкету, тестовое, интервью, оценку | Готовые шаблоны для платформы |
| 8. Перенос в платформу | Переводим пакеты в настройки приложения | Много вакансий в платформе |

## 3. Как собирать финальную оргструктуру

Для каждой найденной версии оргструктуры фиксируем:

- источник;
- дату документа;
- какие направления описаны;
- какие роли указаны;
- кто кому подчиняется;
- какие роли уже существуют;
- какие роли планируются;
- какие роли спорные;
- какие роли дублируются под разными названиями;
- какие функции не имеют владельца.

## 5. Структура пакета роли

Для каждой роли создаем одинаковый пакет.

### 5.1. Карточка роли

- название роли;
- направление;
- грейд;
- руководитель;
- подчиненные, если есть;
- цель роли;
- ценный конечный продукт;
- 5 зон ответственности;
- ожидаемые результаты на 3 месяца;
- ожидаемые результаты на 6 месяцев;
- ключевые показатели;
- обязательные компетенции;
- желательные компетенции;
- культурные критерии;
- красные флаги;
- формат занятости;
- зарплатная вилка;
- условия роста.

### 5.2. Текст вакансии

- коротко о компании;
- зачем открыта роль;
- что предстоит делать;
- какой опыт нужен;
- что будет преимуществом;
- условия;
- как проходит отбор;
- ссылка на анкету.

### 5.3. Анкета кандидата

- контакты;
- опыт;
- профильные вопросы;
- рабочие кейсы;
- инструменты;
- ожидания;
- формат работы;
- стоп-факторы;
- автоматическая оценка.

### 5.4. Тестовое задание

- цель задания;
- что проверяем;
- входные данные;
- формат результата;
- срок выполнения;
- критерии оценки;
- красные флаги.

### 5.5. Интервью

- структура интервью со специалистом по подбору;
- структура интервью с руководителем;
- вопросы по прошлому опыту;
- вопросы по кейсам;
- вопросы по ценностям;
- вопросы по мотивации;
- критерии сильного ответа;
- критерии слабого ответа.

### 5.6. Форма оценки

- оценка специалиста по подбору;
- оценка руководителя;
- оценка искусственного интеллекта по расшифровке;
- итоговая оценка;
- решение по следующему этапу.

### 5.7. Предложение работы

- переменные для предложения;
- стандартный текст;
- условия;
- дата выхода;
- испытательный срок;
- задачи на первые 30 дней;
- критерии успешного старта.

## 6. Приоритет обработки ролей

Предлагаемый порядок:

1. SMM-специалист - уже почти готовый образец.
2. Менеджер проекта - есть локальное описание, нужно достроить пакет.
3. Специалист по подбору - есть анкеты, сценарии и оценочные материалы.
4. Менеджер продаж / квалификатор - важная коммерческая роль.
5. Куратор / специалист сопровождения учеников.
6. Методолог.
7. Продюсер / руководитель запуска.
8. Копирайтер.
9. Монтажер коротких видео.
10. Бухгалтер / финансовый специалист.

## 7. Важная граница

Не нужно сразу превращать все старые материалы в платформу.

Сначала:

1. собрать и согласовать оргструктуру;
2. утвердить справочник ролей;
3. выбрать 3 первые роли;
4. создать для них качественные пакеты;
5. только потом масштабировать на остальные вакансии.

Иначе мы перенесем в платформу старый хаос, просто в более красивом интерфейсе.
