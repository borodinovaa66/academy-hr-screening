# Процесс найма и границы платформы подбора v1

## 1. Что мы на самом деле делаем

Мы расширяем текущую платформу первичного отбора SMM-специалиста до универсального инструмента подбора на разные вакансии.

Цель первой версии расширения: не строить полноценную систему управления подбором, а сделать управляемую систему, где для каждой вакансии можно создать шаблон воронки, анкету, оценку, тестовое задание, правила статусов и действия специалиста по подбору.

## 2. Границы процесса

### Входит в платформу

- создание и хранение шаблонов вакансий;
- публикация ссылки на анкету под конкретную вакансию;
- сбор контактов, резюме, портфолио и ответов кандидата;
- автоматическая первичная оценка;
- выявление стоп-факторов, рисков и сильных сторон;
- автоматическая выдача тестового задания по правилам вакансии;
- хранение записи или ссылки на запись интервью;
- расшифровка интервью;
- независимая оценка интервью искусственным интеллектом;
- независимая оценка интервью человеком;
- сборка предложения работы по шаблону;
- хранение результатов в админке;
- ручное решение специалиста по подбору по дальнейшему этапу;
- аналитика по воронке;
- экспорт или передача данных в рабочие системы.

### Не входит в первую версию

- автоматическое финальное решение о найме;
- полноценное ведение всей кадровой документации;
- расчет зарплат, договоры и адаптация новых сотрудников;
- сложная интеграция с большим количеством площадок поиска кандидатов;
- ИИ-интервью без контроля человека;
- автоматический отказ кандидатам без утвержденных шаблонов коммуникации.

## 3. Базовая воронка найма

| Этап | Кто отвечает | Что происходит | Выход этапа | Автоматизация |
| --- | --- | --- | --- | --- |
| 1. Заявка на подбор | Руководитель / специалист по подбору | Формулируется вакансия, требования, стоп-факторы, зарплатная вилка | Карточка вакансии | Частично |
| 2. Шаблон вакансии | Специалист по подбору / администратор платформы | Создается анкета, оценка, тестовое, статусы | Активный шаблон | Да |
| 3. Привлечение кандидатов | Специалист по подбору / рекрутер | Ссылка размещается в каналах поиска | Поток кандидатов | Частично |
| 4. Анкета кандидата | Кандидат | Заполняет короткий первичный опрос | Отклик в системе | Да |
| 5. Первичная оценка | Платформа | Считает баллы, статус, риски, стоп-факторы | Сильный / спорный / резерв / отказ | Да |
| 6. Тестовое задание | Платформа + кандидат | Сильному кандидату выдается тестовое, кандидат отправляет ссылку | Сданное тестовое | Да, с ручной проверкой |
| 7. Ручной разбор | Специалист по подбору | Проверяет карточку, ответы, резюме, тестовое | Решение по интервью | Человек |
| 8. Интервью со специалистом по подбору | Специалист по подбору | Проводится интервью по структуре, сохраняется запись или ссылка | Расшифровка и две оценки | Частично |
| 9. Решение о втором интервью | Специалист по подбору | Сравниваются оценка ИИ и оценка человека | Допуск к руководителю | Человек |
| 10. Интервью с руководителем | Руководитель-заказчик | Проводится финальное интервью, сохраняется запись или ссылка | Расшифровка и две оценки | Частично |
| 11. Финальное решение | Руководитель-заказчик | Сравнение кандидатов, решение, предложение работы или отказ | Предложение / отказ / резерв | Человек |
| 12. Предложение работы | Руководитель + специалист по подбору | Заполняются переменные, формируется стандартный документ | Предложение отправлено | Частично |
| 13. Принятие предложения | Специалист по подбору | Нажимает кнопку "Предложение принято" | Запуск адаптации | Да |
| 14. Аналитика | Специалист по подбору / руководитель | Смотрим конверсию, качество источников, узкие места | Решения по улучшению воронки | Частично |

## 4. Универсальная модель вакансии

Каждая вакансия должна храниться как шаблон.

Минимальные поля шаблона:

- название вакансии;
- короткое описание роли;
- отдел или направление;
- формат работы;
- зарплатная вилка;
- обязательные требования;
- желательные требования;
- стоп-факторы;
- вопросы анкеты;
- варианты ответов;
- веса ответов для оценки;
- пороги статусов;
- правила выдачи тестового задания;
- текст тестового задания;
- критерии оценки тестового;
- критерии оценки интервью со специалистом по подбору;
- критерии оценки интервью с руководителем;
- веса этапов в итоговой оценке;
- шаблон предложения работы;
- шаблоны коммуникаций;
- ответственный специалист по подбору;
- статус вакансии: черновик / активна / пауза / закрыта.

## 5. Статусы кандидата

Базовые статусы, которые можно использовать для всех вакансий:

- `Сильный` - кандидат подходит для следующего этапа;
- `Спорный` - нужен ручной разбор специалиста по подбору;
- `Резерв` - слабое или неполное соответствие вакансии, можно оставить в базе;
- `Отказ` - кандидат не проходит первичный фильтр;
- `Тестовое выдано` - кандидат получил тестовое задание;
- `Тестовое сдано` - кандидат отправил результат тестового;
- `Интервью` - кандидат приглашен на интервью;
- `Интервью с руководителем` - кандидат допущен к финальному интервью;
- `Предложение` - готовится предложение о работе;
- `Предложение отправлено` - кандидат получил предложение;
- `Предложение принято` - кандидат согласился;
- `Нанят` - кандидат принят;
- `Отказ после рассмотрения` - кандидат отклонен после ручной проверки;
- `Кадровый резерв` - кандидат сохранен для будущих вакансий.

## 6. Человек в контуре проверки

Человек обязательно нужен:

- при утверждении шаблона вакансии;
- при изменении правил оценки и стоп-факторов;
- при просмотре спорных кандидатов;
- при оценке открытых ответов и тестовых заданий;
- при оценке интервью;
- перед допуском к интервью с руководителем;
- перед приглашением на интервью;
- перед отправкой отказа, если отказ содержит персонализированную формулировку;
- перед финальным решением о найме.

ИИ и автоматическая оценка должны помогать сортировать поток, но не должны самостоятельно принимать кадровое решение.

## 7. Что стандартизируем как шаблоны

Повторяющиеся документы и процессы:

- бриф на вакансию;
- карта компетенций;
- анкета первичного отбора;
- матрица оценки кандидатов;
- стоп-факторы;
- тестовое задание;
- критерии оценки тестового;
- структура интервью;
- форма оценки интервью специалистом по подбору;
- форма оценки интервью руководителем;
- карточка кандидата;
- шаблон решения специалиста по подбору;
- шаблон отказа;
- шаблон приглашения на интервью;
- шаблон предложения работы;
- шаблон отчета по воронке.

## 8. Минимальная рабочая версия масштабирования

Минимальная рабочая версия расширения:

1. Добавить поддержку нескольких вакансий.
2. Хранить для каждой вакансии отдельные настройки анкеты и оценки.
3. Сделать список вакансий в админке.
4. Сделать публичную ссылку вида `/v/{кодВакансии}`, где `кодВакансии` - короткое имя вакансии в адресе.
5. Привязать каждого кандидата к вакансии.
6. В админке фильтровать кандидатов по вакансии.
7. Для каждой вакансии отдельно задавать тестовое и пороги.
8. Сохранить текущую SMM-вакансию как первый шаблон.

Это даст бизнес-результат быстрее, чем строить большую систему подбора сразу.

## 9. Следующий проектный шаг

Перед разработкой нужно согласовать документ "Бизнес-процесс найма v1":

- какие этапы точно оставляем;
- какие статусы нужны;
- где автоматизируем;
- где оставляем человека;
- какие роли пользователей нужны;
- какие вакансии берем первыми после SMM;
- какие документы превращаем в шаблоны.

После согласования можно писать ТЗ на расширение платформы до версии с несколькими вакансиями.
