# Тестовые задания для менеджера проектов

## 1. Как использовать

Основное тестовое должно проверять реальную работу роли: задача, сроки, ответственные, риски, проверка готовности, отчетность.

Не нужно давать большое задание на 6-8 часов. Для первичного отбора достаточно 1,5-2,5 часов.

Рекомендуемый основной вариант: **Вариант 1. Разбор мини-запуска и план управления проектом**.

## 2. Вариант 1. Разбор мини-запуска и план управления проектом

### Задание для кандидата

Представьте, что через 10 дней у онлайн-школы проходит открытый вебинар.

Цель вебинара: собрать регистрации, провести эфир, передать заявки в отдел продаж и подготовить отчет по итогам.

Вам нужно как менеджеру проектов организовать подготовку.

### Вводные

Уже известно:

- дата вебинара: через 10 дней;
- ведущий: эксперт школы;
- есть посадочная страница, но ее нужно проверить;
- техническая компания настраивает вебинарную комнату и рассылки;
- дизайнер делает баннеры;
- копирайтер готовит письма и посты;
- отдел продаж должен получить список заявок и вводные по вебинару;
- юрист должен проверить страницу и рекламные формулировки;
- руководитель маркетинга хочет видеть короткий статус каждые 2 дня.

### Что нужно сделать

Подготовьте документ, в котором есть:

1. План работ на 10 дней.
2. Таблица задач: задача, ответственный, срок, статус, что проверить.
3. Список рисков и что вы будете делать с каждым риском.
4. Чек-лист проверки перед запуском трафика.
5. Чек-лист проверки за день до вебинара.
6. Как вы передадите заявки и вводные в отдел продаж.
7. Какие показатели соберете после вебинара.
8. Как будет выглядеть короткий отчет руководителю.

### Формат результата

Google Docs, Google Sheets, Notion или PDF.

Объем: 3-6 страниц или одна таблица с пояснениями.

Срок выполнения: до 24 часов после получения задания.

Реальное время на выполнение: 1,5-2,5 часа.

## 3. Вариант 2. Проверка воронки

### Когда использовать

Подходит, если нужно проверить внимательность к деталям и понимание пользовательского пути.

### Задание

Кандидату дается схема простой воронки:

пост / реклама -> посадочная страница -> форма регистрации -> письмо подтверждения -> вебинар -> передача заявки в продажи.

Нужно:

1. Составить чек-лист проверки воронки.
2. Указать, какие ошибки чаще всего ломают такую воронку.
3. Описать, как кандидат будет тестировать путь пользователя.
4. Подготовить шаблон сообщения техническому подрядчику с найденными ошибками.
5. Подготовить короткий статус руководителю.

## 4. Вариант 3. Отчет по итогам вебинара

### Когда использовать

Подходит для кандидатов, где важно проверить работу с цифрами.

### Вводные

Даны условные цифры:

| Показатель | Значение |
| --- | --- |
| Переходы на страницу | 3 200 |
| Регистрации | 760 |
| Доходимость до вебинара | 310 |
| Досмотрели до предложения | 190 |
| Оставили заявку | 62 |
| Дошли до консультации | 38 |
| Оплатили | 11 |

### Задание

1. Посчитать конверсии по этапам.
2. Найти 2-3 слабых места.
3. Сформулировать выводы для руководителя.
4. Предложить 5 гипотез улучшения.
5. Составить короткий отчет на 1 страницу.

## 5. Критерии оценки основного тестового

| Критерий | Баллы |
| --- | --- |
| Понимание задачи и контекста онлайн-школы | 10 |
| Логика плана работ | 15 |
| Качество таблицы задач | 15 |
| Контроль сроков и ответственных | 10 |
| Проверка технической готовности | 15 |
| Работа с рисками | 10 |
| Коммуникация с продажами и подрядчиками | 10 |
| Отчетность и показатели | 10 |
| Структура и ясность документа | 5 |
| Итого | 100 |

## 6. Пороговые решения

| Баллы | Решение |
| --- | --- |
| 85-100 | Сильный кандидат, звать на интервью с руководителем после интервью с менеджером по персоналу |
| 70-84 | Подходит, разобрать спорные места на интервью |
| 55-69 | Слабый / спорный, только если сильная анкета и хорошая мотивация |
| До 54 | Не проходить дальше |

## 7. Красные флаги в тестовом

- нет сроков;
- нет ответственных;
- нет проверки ссылок, форм, писем и вебинарной комнаты;
- нет рисков;
- нет передачи данных в продажи;
- нет отчета по итогам;
- много красивого текста без управленческой структуры;
- кандидат решает задачу как исполнитель одной функции, а не как координатор проекта;
- нет приоритета: все задачи одинаково важны;
- кандидат не понимает, что руководителю нужен короткий статус, а не длинный поток мыслей.
