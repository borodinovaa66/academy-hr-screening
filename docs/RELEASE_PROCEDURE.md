# Регламент обновления HR-платформы

## Цель

Сотрудники уже работают в платформе, поэтому изменения нельзя выкатывать хаотично после каждой мелкой правки. Обновления должны собираться в понятные пакеты и применяться предсказуемо.

## Правило частоты

Обычные изменения выкатываются пакетами не чаще одного раза в час.

Исключения:

- критическая ошибка, из-за которой нельзя войти в систему;
- потеря или риск потери данных;
- ошибка безопасности;
- неработающая отправка анкеты кандидатам.

Все остальные правки копятся до ближайшего окна выката.

## Рабочее окно выката

Рекомендуемый порядок:

1. В течение часа разработчик собирает изменения в GitHub.
2. Перед выкладкой проверяет список коммитов, которые попадут в пакет.
3. Проверяет синтаксис и базовые сценарии.
4. Обновляет `public/version.json` и номер версии ассетов в `public/index.html`.
5. Выкладывает пакет на сервер.
6. Проверяет доступность сервиса.
7. Сообщает HR/админу, что обновление готово.

## Что видит пользователь

В админке есть кнопка проверки обновлений.

Если версия на сервере новее той, что открыта у пользователя во вкладке, в верхней панели появляется заметное уведомление:

`Готовы обновления → Обновиться`

Пользователь сам нажимает кнопку и обновляет страницу в удобный момент.

## Что обязательно проверять перед выкладкой

Команды:

```powershell
node --check public\app.js
node --check server.js
git status --short
```

Минимальная ручная проверка:

- открывается админка;
- работает вход;
- открывается раздел "Подобрать сотрудника";
- открывается страница вакансии;
- открывается анкета кандидата;
- нет явных ошибок верстки на основном экране.

## Как обновлять номер версии

Перед выкладкой обновить:

- `APP_CLIENT_VERSION` в `public/app.js`;
- `version` и `releasedAt` в `public/version.json`;
- query-параметры ассетов в `public/index.html`, например `v=50`.

Версия должна быть простой и возрастающей, например:

`2026-06-26-01`

Следующий пакет в тот же день:

`2026-06-26-02`

## Команда выкладки

Текущая ручная команда выкладки:

```powershell
scp -i C:\Users\User\.ssh\codex-hr-yandex public\index.html public\app.js public\styles.css public\version.json server.js ubuntu@93.77.178.9:/tmp/
ssh -i C:\Users\User\.ssh\codex-hr-yandex ubuntu@93.77.178.9 "sudo cp /tmp/index.html /opt/hr-screening/public/index.html && sudo cp /tmp/app.js /opt/hr-screening/public/app.js && sudo cp /tmp/styles.css /opt/hr-screening/public/styles.css && sudo cp /tmp/version.json /opt/hr-screening/public/version.json && sudo cp /tmp/server.js /opt/hr-screening/server.js && sudo chown hrapp:hrapp /opt/hr-screening/public/index.html /opt/hr-screening/public/app.js /opt/hr-screening/public/styles.css /opt/hr-screening/public/version.json /opt/hr-screening/server.js && sudo systemctl restart hr-screening && sleep 2 && systemctl is-active hr-screening && rm -f /tmp/index.html /tmp/app.js /tmp/styles.css /tmp/version.json /tmp/server.js"
```

Если серверный код не менялся, `server.js` можно не копировать и сервис можно не перезапускать. Но после изменения серверных заголовков или API перезапуск обязателен.

## Сообщение пользователям после выкладки

Короткий текст для Bitrix24:

```text
В HR-платформе готово обновление.

Если у вас открыта админка, в верхней панели появится кнопка "Готовы обновления". Нажмите "Обновиться", когда закончите текущее действие.

Если кнопки нет, но экран ведет себя странно, просто обновите страницу браузера.
```

## Что не делаем

- Не деплоим каждую мелкую правку сразу.
- Не просим сотрудников постоянно чистить кэш.
- Не меняем одновременно много критичных сценариев без проверки.
- Не выкатываем визуальные эксперименты в рабочее время без необходимости.
